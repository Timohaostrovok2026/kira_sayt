# Переход в новую сессию

Регламент — `docs/WORKFLOW.md` §4. По шагам:

1. **Состояние.** Что сделано в этой сессии, что нет. Незаконченное доведи до проверенного состояния или явно опиши как «не сделано». Выложено ли на сервер — да/нет.
2. **Решения — в файлы.** Каждое решение владельца или Кирилла из этой сессии — в журнале `docs/ROADMAP.md` §3 и в нужных документах (`PRODUCT.md`, `DESIGN.md` §11); технические — `ROADMAP.md` §4; идеи — `docs/FUTURE.md`; итоги проверок — `docs/_reviews/`. Отметь сделанные задачи в `ROADMAP.md` §2. Чего нет — допиши.
3. **Журнал сессии.** Запись в `docs/sessions/ГГГГ-ММ-ДД.md` (AGENTS.md §7): цель, что изменено (файлы и суть), что проверено и как, что не проверено.
4. **Уборка.** Временное — только в `scratch/`; тестовые заявки и тестовые правки контента убраны (AGENTS.md §6).
5. **Статус.** Обнови «Текущий статус» в `CLAUDE.md` — не больше 4 строк, с хешем коммита. Подробности — в `docs/ROADMAP.md`, не в CLAUDE.md.
6. **Проверка и git.** `cd web && npm run verify` — 0 ошибок. Если менялся код и `/code-review high --fix` по этому диффу ещё не запускали — запусти. Коммит в корне проекта (без push); `git status` чистый.
7. **Промпт.** Прошлый промпт из `docs/_handoff/` перенеси в `docs/_archive/handoff/` (`git mv`). Новый — в `docs/_handoff/ГГГГ-ММ-ДД_<задача>.md` по шаблону `docs/WORKFLOW.md` §4 и владельцу в блоке ```text```. Промпт самодостаточный: новая сессия не видит этот разговор. Ссылайся на конкретные разделы документов, а не «прочитай целиком».
   Промпт следующего **этапа** — только по слову владельца. Без него — промпт продолжения текущего этапа.
8. **Финал.** Коротко владельцу: что сохранено, какой коммит, выложено ли, что вставить в новую сессию.
