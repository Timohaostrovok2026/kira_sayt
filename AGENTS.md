# «Улыбайся» — правила проекта для агентов (AGENTS.md)

Сайт агентства детских праздников **«Улыбайся»** Кирилла Мочалова (Москва и МО).
Аниматоры в костюмах (110+ героев), квесты, вечеринки, шоу, мастер-классы, допы, готовые пакеты.
Цель сайта — воронка: клиент листает → собирает праздник в корзину → отправляет заявку менеджеру в один клик.

Эти правила обязательны для основного агента и всех субагентов. Дизайн — в [DESIGN.md](DESIGN.md).
Особенности Next.js 16 — в [web/AGENTS.md](web/AGENTS.md) (файл генерирует `next dev`, не править).

## 1. Принципы

1. **Честность.** Не поддакивать. Видишь ошибку в задаче, риск или антипаттерн — скажи прямо и предложи вариант лучше.
2. **Никаких выдумок в коде.** Next.js 16 отличается от того, что ты помнишь: перед использованием API сверяйся с `web/node_modules/next/dist/docs/`. Не придумывать методы, поля базы, эндпоинты.
3. **Никаких выдумок в контенте.** Цены, программы, состав — только из каталога (админка или база). Отзывы — только настоящие. Цифры доверия — только подтверждённые Кириллом.
4. **Без манипуляций.** Не делать ложный дефицит («осталось 2 места»), фейковые таймеры и выдуманные скидки. Срочность — только правдивая («декабрь бронируют первыми»).
5. **Не выделять VIP.** VIP-костюмы на сайте не показываются (решение Кирилла), об этом говорит менеджер. `e_vip` остаётся в данных, но скрыт через `SPECIAL_EXTRAS`.
6. **Онлайн-оплаты нет.** Заявка → менеджер → согласование → предоплата → праздник. Не добавлять платёжные формы без прямого решения Кирилла.

## 2. Проверка перед «готово»

Не сообщать «готово», пока не прогнаны проверки. Говорить, что именно проверено, а что нет.

| Изменение | Обязательно |
|---|---|
| Любой код | `cd web && npm run verify` (tsc + eslint + тесты) — без ошибок |
| Перед выкладкой | `npx next build` локально — успешно |
| Интерфейс | Просмотр в браузере на **375–390 px** и **1366 px**; нет горизонтального скролла; анимации и lazy-загрузка в свёрнутой панели браузера не работают — для проверки отключать их скриптом, а не считать багом |
| Цены, корзина, пакеты | Ручная проверка сумм на 2–3 примерах (пакет со скидкой, выезд за МКАД, звук) |
| Админка | Правка → сохранение → изменение видно на публичной странице → откат правки |
| Заявки | Тестовая заявка доходит в базу (и в Telegram, когда подключён бот), затем удалить её |

**Тесты.** `node --test` (Node сам понимает TypeScript), файлы `*.test.ts` рядом с кодом, импорт с расширением `.ts`; запуск — `npm test`, входят в `npm run verify`. Есть: цена пакета (`src/data/catalog.test.ts`). При изменении чистой логики (`calcPackagePrice`, `buildLines` в корзине, запросы статистики, валидация контента) — добавлять тесты. Логику, которую нельзя проверить без React или базы, выносить в чистые функции в `src/data/`.

**Независимая проверка** после партии изменений — агенты `verifier-decisions`, `verifier-tech`, для денег и корзины `code-breaker` (`.claude/agents/`, порядок — `docs/WORKFLOW.md` §2). Перед коммитом кода — `/code-review high --fix`.

## 3. Данные — самое ценное

- **Боевая база — на сервере** (`/var/lib/ulybaysya`): там правки Кирилла, заявки и статистика. Локальная `web/data` — песочница, она расходится с боевой и это нормально.
- **Никогда** не перезаписывать серверную базу локальной. Выкладка — только через `web/scripts/deploy.sh`: он не трогает `/var/lib/ulybaysya`.
- Перед изменением схемы базы или формата контента — копия: `sqlite3 /var/lib/ulybaysya/site.db ".backup '/var/lib/ulybaysya/backup-ДАТА.db'"`. Миграции — идемпотентные (`CREATE TABLE IF NOT EXISTS`, проверка колонок), без потери данных.
- **Не писать в SQLite из второго процесса**, пока работает сервер Next (в том числе `seed-stats.mjs`). Это уже ломало соединение сервера. Сначала остановить сервер, потом скрипт.
- `seed-stats.mjs` — только для локальной демонстрации. На сервере не запускать.
- **id позиций неизменны** (`p_*`, `e_*`, `k_*`, `c_*`): на них ссылаются корзины клиентов, пакеты и статистика. Убрать с сайта — «скрыть», а не удалить.
- Каждое сохранение в админке пишет прошлую версию в `content_history` (50 последних на ключ) — откат возможен вручную.
- **Резервные копии:** каждую ночь в 03:30 МСК cron (`/etc/cron.d/ulybaysya-backup`, пользователь `uly`) запускает `web/scripts/backup.sh` → `/var/backups/ulybaysya/ulybaysya-ГГГГ-ММ-ДД.tar.gz` (база через `.backup` + `uploads/`, 14 последних), лог — `/var/log/ulybaysya-backup.log`. Тот же архив уходит в Яндекс Облако (бакет `ulybaysya-backup-2026`; ключ сервисного аккаунта с ролью `storage.uploader` — только загрузка — в `/etc/ulybaysya-backup.env`, правит владелец). Скачать копию из облака — через консоль Яндекс Облака владельцем. Восстановление — только остановив службу и с копией текущей базы.

## 4. Архитектура и стиль кода

- **Публичный сайт** — в группе `(site)`: шапка, корзина, нижнее меню, аналитика. `/admin` и `/stats` — отдельные, без публичной шапки и без трекинга.
- **Контент** живёт в базе. На сервере: `getCatalog()`, `getCatalogData()`, `getSiteContent()` (`src/lib/content/get.ts`, кэш с тегом `catalog`). В клиенте: `useCatalog()`, `useSite()` (`src/lib/catalog-context.tsx`). Статические импорты каталога в компонентах запрещены — `catalog.json` и `SITE_SEED` только для первичного заполнения базы.
- После записи контента — `updateTag("catalog")`, чтобы сайт обновился сразу.
- **Чистые функции** (цены, возраст, разбор текстов) — в `src/data/catalog.ts`, без React и без базы.
- **Общие карточки** — `src/components/cards.tsx` (`ProgramCard`, `CostumeCard`, `ExtraCard`, `PackageCard`, `SectionHead`, `AddToggle`). Новые страницы используют их, а не копируют разметку.
- **Размер файла** — ориентир до ~400 строк; больше 500 — разбить на модули. Сейчас крупнее всех `src/lib/stats/queries.ts` (~530) — разбить при следующей правке.
- Комментарии — по-русски, коротко, объясняют «почему», а не «что».
- Тексты интерфейса — русские, на «вы», коротко.

### Next.js 16 — частые ловушки
- `cacheComponents: true`: нельзя `export const dynamic` / `revalidate`. Динамику (cookies, база, `Date.now()`) читать внутри `<Suspense>` или после `await connection()`; кэшируемое — через `"use cache"` + `cacheLife` + `cacheTag`.
- `params` и `searchParams` — это Promise, их надо `await`.
- `useSearchParams` в клиентском компоненте — только внутри `<Suspense>`.
- В серверных компонентах не вызывать `new Date()` вне кэша или динамической зоны.
- Server actions ограничены 1 МБ — загрузка фото идёт через route handler `/admin/upload`.

### Аналитика
- Важные кнопки и ссылки размечать `data-track="зона_действие"` (например `hero_build`, `program_add_<id>`). Клики по контактам (tel, WhatsApp, Telegram, Instagram) ловятся автоматически.
- Новое событие или новый `data-track` — добавить человеческое название в `src/lib/stats/labels.ts`, иначе в статистике будет сырой id.

## 5. Безопасность

- Секреты только в переменных окружения: `STATS_PASSWORD`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `NEXT_PUBLIC_YM_ID`, `DATA_DIR`. Локально — `web/.env.local`, на сервере — `/etc/ulybaysya.env`. Шаблон — `web/.env.example`. В код, в git и в чат не попадают.
- `/admin`, `/admin/upload` и `/stats` — только с cookie авторизации (`src/lib/auth.ts`). Любой новый админский маршрут проверяет её на сервере.
- Пользовательский текст (заявки, отзывы, контент из админки) — только через JSX, без `dangerouslySetInnerHTML`.
- Загрузки: только изображения, перекодирование через `sharp` в webp, пути без `..`.
- Не открывать сервер шире портов 22, 80, 443 (ufw).
- Код — в **публичном** репозитории https://github.com/Timohaostrovok2026/kira_sayt (`origin`, ветка `main`). Всё, что коммитится, видят все: секреты, пароли, данные клиентов (заявки, телефоны), выгрузки базы — никогда в git. Push — после проверенного коммита; `--force`, удаление веток и смена видимости — нельзя.
- Хук `.claude/hooks/block-destructive.sh` механически блокирует необратимые команды (`rm -rf` вне `scratch/` и `.next`, `git reset --hard`, `git push --force`), чтение `.env` и ключей SSH, запись в боевую базу через `scp`/`rsync`, `seed-stats` на сервере, `DROP TABLE` и `DELETE` без условия. Сработал — не обходить, а спросить владельца.

## 8. Работа с субагентами

Подробно — `docs/WORKFLOW.md` §2. Делим работу **по контексту, а не по типу задачи**.

- **Код пишет основная сессия.** Субагенты — для консилиума (`/council`), независимой проверки и поиска по большому объёму.
- **Субагент-автор** — только для почти независимого куска со своими папками (новая страница, раздел админки). Цепочек «пишет → дописывает → правит» не делаем: детали теряются на каждой передаче.
- **Владение файлами:** каждому пишущему субагенту — свои папки. Общие модули (`cards.tsx`, `cart.tsx`, `catalog.ts`, `globals.css`, layout) меняет только основной агент; субагент описывает нужную правку в отчёте.
- В бриф субагента — ссылки на этот файл, `DESIGN.md`, `docs/PRODUCT.md` и на ловушки Next.js 16 из раздела 4.
- Субагенты не запускают свой `next dev`/`next build`, если уже работает сервер основного агента, и не пишут в базу из отдельного процесса.
- Отчёт субагента — не доказательство. Основной агент сам смотрит результат в браузере и прогоняет проверки из раздела 2.
- **Постоянные проверяющие** (`.claude/agents/`, Opus, high): `verifier-decisions` — решения и честный контент; `verifier-tech` — код, Next 16, данные, безопасность; `code-breaker` — мутации в логике денег и корзины в своей копии репозитория. После партии изменений — волна 1 из двух первых; для крупных изменений (новый раздел, корзина, данные, авторизация) — ещё `code-breaker` и `/security-review` до выкладки.

## 9. Выкладка

```bash
cd web && ./scripts/deploy.sh
```

Скрипт: заливает код → при изменении `package-lock.json` везёт кэш пакетов → `npm ci --offline` → `next build` → перезапуск службы → проверка ответа.

Полезное на сервере:
- логи сайта: `journalctl -u ulybaysya -n 100`
- логи HTTPS: `journalctl -u caddy -n 100`
- перезапуск: `systemctl restart ulybaysya`

После выкладки — открыть https://195.133.73.111 и пройти главную, конструктор, корзину и админку.
