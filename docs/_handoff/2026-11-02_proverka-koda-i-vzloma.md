## Часть Б — попытка взлома
Два взгляда, независимо:
- **Белый ящик:** `/security-review` по всему коду + свой разбор.
- **Чёрный ящик:** отдельный субагент-«злоумышленник» (general-purpose), который НЕ читает код, знает только адрес `localhost:3200` и что там есть админка; атакует curl-ом и браузером и приносит список того, что получилось. Свой next-сервер он не запускает и в базу не пишет.

Минимум, что проверить (и записать «держит / не держит»):
1. **Вход без пароля:** `/admin`, `/stats`, `/admin/upload`, `/media/*` без куки; с подделанной, старой, пустой, чужой длины кукой; после выхода.
2. **Server actions — отдельные открытые точки входа.** Каждую функцию из `src/app/admin/actions.ts`, `admin/leads-actions.ts`, `stats/actions.ts` вызвать напрямую POST-запросом с её id без куки — каждая обязана сама проверять вход на сервере, а не надеяться на страницу.
3. **Пароль:** перебор (локально) — есть ли ограничение попыток и задержка; что будет без `STATS_PASSWORD` и без `STATS_SECRET` в боевом окружении (ключ по умолчанию `uly-stats-v1` лежит в публичном репо — проверить, задан ли свой; сам файл не читать, спросить меня); флаги куки (`HttpOnly`, `Secure`, `SameSite`), срок.
4. **Чужой сайт от нашего имени:** CSRF на server actions и маршрутах (запрос с другим Origin), встраивание админки во фрейм (clickjacking).
5. **Заявки `/api/lead`:** спам (есть ли лимит по IP, honeypot), огромные и кривые тела, лишние поля, отрицательные и подменённые цены в корзине (сумма должна считаться с сервера, а не браться у клиента), HTML/скрипты в полях → как они выглядят в админке и в Telegram (экранирование под `parse_mode`, юнит-тест в `src/data/notify.test.ts`).
6. **Аналитика `/api/track`:** можно ли раздуть базу мусором, подменить события, вставить текст, который сломает `/stats`.
7. **Загрузка фото:** без входа; не картинка; SVG с JS; картинка-бомба (огромное разрешение при малом весе); файл больше лимита; имя с `../`.
8. **Отдача файлов `/media/[...path]`:** обход путей (`..`, `%2e%2e`, `%2f`, двойное кодирование), чтение `site.db`, `.env`, файлов вне `uploads/`.
9. **Утечки:** ответы с ошибками (стек, пути), source maps в `/_next`, служебные файлы (`/.env`, `/.git`, `/data/site.db`, `/package.json`), секреты и телефоны клиентов в истории git (`git log -p` по всей истории, поиск токенов и номеров).
10. **Сервер (по SSH, только чтение):** открытые порты снаружи и `ss -tlnp` (служба только на 127.0.0.1:3000), `ufw status`, вход по паролю выключен, права на `/etc/ulybaysya.env`, `/etc/ulybaysya-backup.env`, `/var/lib/ulybaysya`, `/var/backups/ulybaysya`; автоустановка обновлений безопасности; версии Node, Caddy, Next — есть ли известные дыры.
11. **HTTPS и заголовки боевого:** редиректы с http и со старых доменов, HSTS, `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`/`frame-ancestors`, CSP (хотя бы для `/admin`), версия сервера в заголовках.
